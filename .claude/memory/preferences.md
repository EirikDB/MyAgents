# User Preferences

_Accumulated from sessions. Read at session start._

## Communication style

- Wants to see what each agent is doing and interact with them directly — transparency over black-box summaries.
- Prefers building iteratively: start with the smallest working thing, then evolve.
- Asks "why" questions about approach — explain reasoning, not just output.

## Build preferences

- Start with the simplest stack that works (plain HTML before frameworks, localStorage before a database).
- Phase-gate: prove the core loop works before adding complexity.
- Single-file deliverables preferred for prototypes.

## What to avoid

- Over-engineering v1. Don't add abstraction layers, plugin systems, or config knobs the user hasn't asked for.
- Silently skipping agent interactions — the user wants to see agents working, not just a final result.
